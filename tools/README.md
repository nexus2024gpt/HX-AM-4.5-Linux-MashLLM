# tools/ — что тут и зачем

Разовые скрипты обслуживания архива артефактов и графа инвариантов. Ничего отсюда не
импортируется рантаймом сервера (`hxam_v_4_server.py`) — это операторские инструменты,
запускаемые вручную из корня проекта.

## Активные утилиты (безопасно использовать)

| Скрипт | Назначение | Безопасность повторного запуска |
|---|---|---|
| `rebuild_graph_knn.py` | **Единственный корректный** способ пересобрать `artifacts/invariant_graph.json` с нуля — text-embeddings + k-NN (топ-K соседей), см. докстринг за объяснением, почему пороговый подход не работает на плотном корпусе | Да, идемпотентно перезаписывает граф |
| `check_graph.py` | Read-only: печатает число узлов/рёбер графа | Да, чисто читающий |
| `patch_graph.py` | Аддитивный патч атрибутов узлов/рёбер (ничего не удаляет), есть `--backup` | Да |
| `verify_migration.py` | Отчёт по качеству архива (покрытие `four_d_matrix`), `--fix` чинит явные диапазонные ошибки | Да, диагностика + опциональный safe-fix |
| `update_graph_with_stability.py` | Дописывает в граф результаты стресс-теста (`stability_score`, `math_model`) и пересчитывает веса рёбер | Да, запускать после каждого батча стресс-тестов |
| `migrate_mgap_registry.py` | Добавляет новые поля (`dimensional_basis`, динамические пороги) в `mgap_registry.json` | Да — пишет в `mgap_registry_v2.json`, оригинал не трогает |
| `repair_edge_resonance.py` | Пересчитывает `four_d_resonance` и `weight` на рёбрах графа, не меняя топологию. Вес всегда считается от базы, поэтому буст не накручивается | Да, идемпотентно; бэкап в `backups/` |
| `purge_artifacts.py` | Согласованное удаление из всех 4 хранилищ (файл→`trash/`, граф, оба индекса). `--orphans` вычищает записи без файла артефакта | Да; бэкап в `backups/` |
| `dedupe_indexes.py` | Убирает дубли id в `semantic_index.jsonl`/`four_d_index.jsonl`, оставляя запись, согласованную с артефактом | Да; бэкап в `backups/` |

> **Почему `purge_artifacts.py` нужен отдельно от API:** штатный `DELETE /artifact/{id}`
> в `hxam_v_4_server.py` чистит файл, граф и `semantic_index`, но **не трогает
> `four_d_index.jsonl`** — записи там накапливаются. Он также не умеет чистить «сирот»
> (записи в графе/индексах, чей файл удалён мимо API).

## Разовые исторические миграции (уже применены — не перезапускать вслепую)

Эти скрипты чинили артефакты под конкретную версию пайплайна и, вероятно, уже отработали на
существующем архиве. Перед повторным запуском проверить `--dry-run`, если он есть.

| Скрипт | Версия | Что чинил |
|---|---|---|
| `clean_artifacts.py` | v4.2 | Лишние пробелы в JSON-ключах/значениях от LLM-форматирования |
| `fix_artifacts_phenomenal.py` | v4.2 | Ретроактивно понижал завышенный вердикт PHENOMENAL → NOVEL по 3 критериям |
| `migrate_portals.py` | v4.2 | Формат hyx-portal артефактов → добавление `four_d_matrix` |
| `migrate_to_v42.py` | v4.0 → v4.2 | Добавление `four_d_matrix` через LLM-вызов ко всем старым артефактам (делает реальные LLM-запросы — не бесплатно и не мгновенно) |
| `migrate_general_domains.py` | v4.6 | Переклассификация артефактов с `domain='general'` на конкретный домен (keyword → семантика → опционально LLM) |

## `archive/` — заведомо устаревшее или сломанное

Оставлено для истории, **не использовать**:

- `rebuild_graph_clean.py`, `restore_graph.py`, `build_graph_from_index.py` — три
  последовательные попытки пересборки графа до `rebuild_graph_knn.py`; первые две дают
  вырожденный граф-клубок на плотном корпусе (см. `SUPERSEDED`-пометку в каждом файле).
- `install_and_run.ps1`, `install_and_run_v42.ps1`, `run_archivist.ps1`,
  `run_stress_batch.ps1` — PowerShell-скрипты Windows-эпохи проекта, до переезда на
  WSL2/Linux (см. `README.md` в корне). Актуальный запуск — `start_hxam_v45.sh`.
